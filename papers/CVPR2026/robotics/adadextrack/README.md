# AdaDexTrack: Dynamic Modulation for Adaptive and Generalizable Dexterous Manipulation Tracking

核对日期：2026-10-22。实验数值均为作者报告；本地完成原文阅读与讲解自检，未复现实验。

## 一句话总结

AdaDexTrack把通用灵巧手跟踪器当作技能载体，通过闭环调整参考轨迹、物体潜变量和关节目标来缓解误差累积；真实实验改善了达标帧比例，但没有证明复杂操作已可稳定完成。（PDF第1–5、8页）

## 研究背景与动机

语言生成的人手运动既有噪声，也不完全适配机器手的关节与接触方式。固定参考轨迹使跟踪器不断追赶偏离状态，微小误差可能在长时程中放大。该论文主张参考本身也应进入反馈环，而不是只在低层动作上纠偏。输入语言先变成手物交互参考，执行阶段并非直接由语言模型每步输出动作。（PDF第1–3页）

### 先把问题放回一次真实执行

假设指令是“用右手拿起这个物体并转一个方向”。语言不是直接转成每个电机的力矩，而是先经DiffH2O产生人手与物体随时间变化的参考动作，再重定向为机器手能理解的参考。控制器每一步同时看到“现在在哪里”和“接下来应该到哪里”，输出机械臂与手的关节命令。本文重点是：参考可能有噪声，执行也不完美，因此不能只追固定参考，还要在反馈中修正参考、物体条件和最终动作。（§3–3.2，PDF第3–5页）

| 量 | 含义与形状 | 与动作的关系 |
|---|---|---|
| \(\hat q_t^h\in\mathbb R^{22}\) | 参考关节位置，6个臂关节+16个手关节 | 期望关节配置 |
| \(\hat p_t^h\in\mathbb R^{5\times7}\) | 四指尖与手腕的刚体位姿 | 每个位姿3维位置+4维旋转表示 |
| \(\hat p_t^o\in\mathbb R^7\) | 参考物体位姿 | 手需要带动物体实现的运动 |
| \(s_t^{prop}\) | 当前机器人本体观测 | 正文没有完整列出其所有分量和总维度 |
| \(s_t^o\) | 当前估计物体位姿 | 真机由视觉位姿估计提供 |
| \(f^o=E_{pc}(P)\in\mathbb R^{64}\) | 物体点云的潜在编码 | 选择已有跟踪行为的条件接口 |
| \(a_t,\Delta a_t\in\mathbb R^{22}\) | 跟踪器相对关节位置命令及残差 | 合成后交给PD控制器 |

参考中的一帧有22+5×7+7=64个数，当前与未来 \(k\in\{0,1,2,4,12\}\) 五帧拼接便有320个参考数。这是根据正文符号推得的展平计数，不是作者公布的完整观测维度；本体观测、预处理、相对坐标表达和调制动作参数化还需要实现核对。7维位姿也不是7个自由度：四元数有单位长度约束。（PDF第3–4页）

### 图2的左右两侧不能当成同一个训练步骤

左半图构建可复用的跟踪技能：文本生成参考→人机重定向→训练多个PPO专家→收集成功数据→行为克隆为一个通用跟踪器。右半图是在这个跟踪器之上训练调制器：通用跟踪器冻结，调制器读取执行状态并输出三类调节。真机执行只需要训练好的通用跟踪器和调制器，不会现场重新训练整组专家。（Fig.2，PDF第4页；图中的火焰/雪花分别表示训练/冻结）

## 核心创新与关键设计

### 1. 从语言参考到机器人的运动学目标

DiffH2O先产生人的手—物体轨迹。人手的关节、长度和机械手不同，所以“把人的关节角直接复制过去”不是重定向。作者人工指定人手与机器手网格的对应点，通过最小化对应点距离来求机器臂手链的参考运动学序列。结果是期望姿态序列，不是已经满足接触动力学的可执行控制信号；生成噪声和接触不一致仍要由后续策略补偿。（§3.1，PDF第3–4页）

文本改写用于增加参考数据覆盖：在1,333条标注中筛选单手、无臂手碰撞、始终可达的505条，九种改写加原描述生成5,050条，再筛成2,765条。此过程增加的是参考种类，不保证每条生成轨迹都物理正确。论文使用GPT-5做语言改写是上游研究设置，本次阅读没有调用该API。（PDF第3、5–6页）

### 2. 专家策略到底观察和预测什么？

定义参考手状态 \(\hat s_t^h=(\hat q_t^h,\hat p_t^h)\)，物体参考 \(\hat s_t^o=\hat p_t^o\)。策略输入由当前状态与参考窗口拼接：

\[
o_t^{track}=\left[s_t^{prop},s_t^o,f^o,\operatorname{concat}_{k\in\{0,1,2,4,12\}}(\hat s_{t+k}^h,\hat s_{t+k}^o)\right].
\]

为什么看未来？只看当前目标，可能在接触发生时才知道该收手还是继续运动；近未来参考让策略提前准备方向和手型。但这些是已生成轨迹的未来目标，不是提前看到了未来真实传感器状态，因此不属于非因果观测泄漏。（PDF第4页）

跟踪策略 \(a_t=\pi^{track}(o_t^{track})\)输出22维相对关节位置变化，作用到机器人后由物理系统产生下一状态。策略既要跟随手的目标，也要让物体跟随目标：手指角度看起来正确但物体滑落，不算好的跟踪。专家针对一条标注及其语义一致的扩展轨迹学习，缩小单个策略需要探索的行为范围。（PDF第3–4页）

### 3. 奖励的四项分别在管什么？

原文式(1)可整理为以下误差项的加权组合：

\[
r_t=\omega_1\|q_t^h-\hat q_t^h\|^2+
\omega_2\|p_t^h-\hat p_t^h\|^2+
\omega_3\|p_t^o-\hat p_t^o\|^2+
\omega_4\|p_t^h-p_t^o\|^2.
\]

第一项约束22个关节，避免只让末端位置碰巧接近却采用错误手型。第二项约束四指尖和手腕的空间位姿，让接触相关部位对齐。第三项约束物体本身，让策略学会真正改变物体。最后一项是手物接近项，鼓励形成接触机会，而不是隔着空间追参考。（PDF第4页）

这四项并非可以直接按印刷式照抄成实现。论文称它为reward，但写的是正号连接误差；若PPO最大化奖励，误差权重符号或奖励变换就决定优化是否正确。手的5×7位姿与物体7维位姿之间怎样取距离、旋转误差怎样度量、哪些部位和时段启用接近项，正文也未完整说明。这里讲清各项意图，权重、符号、广播和实际距离函数仍以补充材料/代码为准，不能假设任意四元数欧氏误差就是最终实现。

专家使用PPO。作为强化学习基础补充，它优化的是策略在模拟环境中得到的折扣回报 \(\mathbb E\sum_t\gamma^tr_t\)，而不是拿每一帧参考动作当成标准答案做监督回归。动作影响未来接触状态，因而奖励可能在多步之后才反映某个动作的好坏；这也是运动学参考仍需要动力学策略的原因。本文没有提供足够细节核对全部PPO损失、网络层数或终止条件。（PDF第3–4页）

### 4. 从许多专家蒸馏成一个跟踪器，技能存在哪里？

对每个专家收集成功执行轨迹，保存它在观测o下输出的动作a，合并成离线数据D。通用跟踪器用行为克隆学习这些状态—动作对。图2给出的概念目标是策略输出与专家动作的L2差：\(L_{BC}\sim\|a_{generalist}-a_{specialist}\|_2\)。图示没有完整规定对时间与样本取平均、是否平方，不能从示意式补出最终代码的全部损失约定。（PDF第4页）

专家信息因此进入**一个网络的权重及其条件响应**，而不是在真机上保存一张“遇到物体A就调用专家A”的查找表。物体潜变量f也存入每个训练样本，让同一网络知道当前几何条件。作者选择离线BC，避免DAgger需要学生反复访问环境并现场询问大量专家的开销；代价是学生偏离专家数据分布时，离线模仿不能自动补齐纠错示范。

这解释了为什么已有通用跟踪器还需要调制器：蒸馏保留了技能覆盖，却未保证学生在每种噪声状态都能恢复。训练表中的通用跟踪器单独使用并不一定比所有已有方法好，后续调制才是关键增量。

### 5. 参考调制R：先改“接下来追哪里”

原文对未来 \(k\in\{1,2,4,12\}\) 的手或物体参考使用残差更新：

\[
\hat s_{t+k}^x\leftarrow\hat s_{t+k}^x+\lambda_xa_{t+k}^{ref,x},\qquad x\in\{h,o\}.
\]

调制器根据当前偏差，提供未来目标的小改动；λ控制改动幅度。跟踪器随后看到的是修正过的参考，而不是仍被迫一步追上原目标。R作用在策略输入侧，与在电机输出上直接加力不同。（§3.2，PDF第5页）

**位置例子（仅解释用）。** 原参考希望物体在下一小段到x=10cm，实际还在x=7cm。调制器可能把近未来目标暂时改到8cm，使跟踪器先恢复可行接触，再逐步靠回原轨迹。这里的7/8/10不是论文测量值，也不表示作者采用固定距离规则；调制量来自学得策略，可能同时考虑转动、手型和后续动作。

为什么不能总把目标改成当前位置？这样会得到很小的局部跟踪误差，却可能停止完成原任务。调制器训练仍受与跟踪器一致的任务目标约束，意图是在原始任务与可执行参考之间折中；具体奖励是否使用原参考、调制参考及其附加约束，需要补充实现核查，正文未给完整公式。原地累计修改还是每步从原始轨迹重建窗口、末尾越界如何填充、旋转残差如何保持合法，也不能从“加一个残差”自行决定。（PDF第5页）

### 6. 潜变量调制O：改变“用哪一种已有跟踪习惯”

基线在任务开始用点云得到固定 \(f^o=E_{pc}(P)\)，执行中保持不变。AdaDexTrack允许调制器输出 \(\tilde f_t^o\in\mathbb R^{64}\)，将其替换进跟踪器观测：

\[
a_t=\pi^{track}\big(s_t^{prop},s_t^o,\tilde f_t^o,\hat s_t^{track}\big).
\]

这里改的是**跟踪器的条件表示**，不是把真实物体换成另一个，也不是每一步重新训练点云编码器。由于蒸馏时不同物体和动作在条件空间中形成不同响应，改变潜变量可以调动不同抓取或手型倾向。（PDF第5页）

用前面的物体例子继续：接近阶段希望手更张开，避免提前碰撞；接触后希望握紧以减少滑动。图5给出潜变量改变与手开合相关的定性例子，说明此接口能影响动作风格。但64维向量没有普遍定义的“更大”顺序，不能据例子把它简化为一个单调控制手开合的标量旋钮。新潜变量是否落在训练流形附近、怎样限制范围、与原编码是替换还是具体残差参数化，需查代码；连续网络也不保证任意插值都能产生有效技能。（PDF第5、7–8页）

### 7. 目标调制T：最后改“这一步的关节命令”

跟踪器读完修正参考和潜变量后输出a，调制器还提供22维小残差：\(a'_t=a_t+\Delta a_t\)。R和O都通过冻结跟踪器间接影响动作，T则直接在输出侧补偿剩余误差，例如轻微接触滑动或执行偏差。作者称其为有界修正，但正文没有列出所有关节的上下界和缩放值。（PDF第5页）

下游是关节空间PD控制。作为控制基础补充，常见形式为 \(\tau=K_p(q_{target}-q)-K_d\dot q\)，把位置误差和速度阻尼变成力矩；本文的22维a是相对位置目标，而不是该式里的力矩τ。a怎样累计成绝对目标、控制频率、力矩限幅、前馈和重力补偿等不能由这个通用公式补猜。（PDF第3、5页）

例如某手指目标变化0.02rad，T给出-0.005rad的解释性残差，合成变化就是0.015rad；PD再根据当前关节状态执行。这组数字只是展示加法，不是作者超参数或安全限值。大的T可能压过原跟踪器，失去“复用已有技能”的意义，因此残差界与任务目标是重要复现条件。

### 8. 一步控制的完整顺序与训练时的信用分配

概念执行顺序如下；它说明信息依赖，不冒充作者实际程序和频率配置：

```text
任务开始：语言→HOI参考→机器人参考；物体点云→初始物体编码
每个控制周期t：
    读取机器人本体状态与估计物体位姿
    取原参考的当前/未来窗口
    调制器读取执行状态和参考条件
    生成参考修正R、物体潜变量O、关节残差T
    将修正参考与潜变量送入冻结的通用跟踪器
    跟踪器输出22维相对关节目标a
    合成a'=a+关节残差，转换并交给PD执行
    感知下一状态，再进入下一周期
```

“冻结”仅指不再用梯度更新跟踪器权重，并不意味着跟踪器每步输出相同；输入变了，动作就会变。调制器训练仍是环境交互的RL：其决策通过跟踪器、PD和物理环境影响奖励。不能因为图中跟踪器冻结就说不需要环境探索，也不能默认训练会通过真实物理系统精确反向传播。正文没有完整给出调制器观测向量、动作总维度、优化器与频率，本笔记不补一个虚构配置。（Fig.2与§3.2，PDF第4–5页）

从成本看，多个专家的RL训练、成功轨迹存储、BC蒸馏、调制器RL构成不同阶段；部署只运行剩余组件，但还要支付物体感知和控制计算。论文正文没有端到端延迟表，不能从“复用冻结策略”推出实时速度保证。

### 9. 真机迁移：策略零样本不等于硬件零校准

真机采用XArm6与LEAP Hand，FoundationPose提供物体位姿，Tsai–Lenz做手眼标定。作者先收集多频率、多幅度正弦关节命令的真实响应，再用CMA-ES搜索模拟器的关节刚度P与阻尼D，使模拟和真实关节轨迹的平方误差尽量小：

\[
(P^*,D^*)=\arg\min_{P,D}\sum_{m,t}\|q_{m,t}^{sim}(P,D)-q_{m,t}^{real}\|^2.
\]

这相当于先让模拟里的“弹性与阻尼响应”接近真机，再在其周围随机化机器人参数、物体质量/摩擦/恢复系数、初始物体位姿以及观测和动作噪声，使策略不只适应一个理想参数点。CMA-ES是辨识阶段的黑箱搜索，不是每个控制周期在线重估一遍。（§3.3，PDF第5页）

作者还使用高摩擦胶带，并在真实评估中排除轴对称导致位姿歧义的物体。因此zero-shot指不在真机任务上继续训练策略，不表示没有真实数据采集、手眼标定、动力学辨识或硬件调整。三类调制能缓解某些偏差，但无法单靠学得残差消除全部错误感知。（PDF第5、8页）

### 10. 为什么需要三个接口，而不是三个名字？

回到“物体已落后、手型不合适、局部还有滑动”的同一时刻：R改变追踪路径的近未来目标，O改变冻结策略所使用的行为条件，T补上这一步残余关节修正。它们分别位于目标、表示和动作层，因而能力和风险不同。R可能过度偏离原任务，O可能进入未训练潜变量区域，T可能绕过技能结构；所有接口都不是独立的安全保证。

表1在未见物体场景加入O后，Completion从R+T的47.51升至53.78，支持表示调制的实际价值；但未见轨迹中完整R+O+T的77.92反低于R+T的80.42。因此“接口互补”是设计动机和部分实验支持，不能翻译成每加一个模块、每个指标都会单调上升。（PDF第6–8页）

## 实验与关键结果

可行性筛选后有2,765条轨迹、50个物体。未见轨迹分割2,212/553；未见物体分割45个物体2,520条训练、5个物体245条测试，在Isaac Gym评估。Mean-error成功率要求整条平均误差达标；Completion是逐帧达标比例再跨轨迹平均，两者不能互换。（PDF第5–6页）

| 表1作者结果 | DexTrack | 通用跟踪器 | R+O+T |
|---|---:|---:|---:|
| 未见轨迹Mean-error/%↑ | 76.13 | 62.20 | 88.99 |
| 未见轨迹Completion/%↑ | 73.89 | 65.01 | 77.92 |
| 未见物体Mean-error/%↑ | 39.59 | 24.08 | 46.12 |
| 未见物体Completion/%↑ | 47.37 | 42.52 | 53.78 |
| 未见物体位置误差/cm↓ | 18.06 | 21.74 | 15.45 |

真实XArm6+LEAP Hand由FoundationPose估计位姿。60条未见轨迹、15物体的Completion从26.63升至52.36%；20条未见物体轨迹、2物体为22.27→36.71%。这些是达标帧比例，不能称为52.36%的整项任务成功率。（表2，PDF第8页）

## 消融实验与证据强度

未见轨迹中，R使Mean-error从62.20升至67.09，R+T为84.45，R+O+T为88.99；但Completion从R+T的80.42降到全模块77.92，手腕和手指误差也并非单调改善。正文“增加组件一致改善”需要限定指标，不能覆盖表中反例。（PDF第6–7页）

## 局限与讨论

真实测试主动排除了位姿对称歧义物体，系统仍依赖明确6D位姿。所谓zero-shot指策略不在真实任务中微调；此前仍采集真机正弦运动做系统辨识，并给指尖和物体贴高摩擦胶带，因此不等于完全无真实数据或硬件调整。基线DexTrack不含未公开的同伦示范挖掘，ObjDex部分组件由作者重实现，比较不能无条件代表原系统最高性能。表1旋转误差列标rad、正文解释写degrees，引用数值时应保留并核对单位差异。（PDF第5–8页）
