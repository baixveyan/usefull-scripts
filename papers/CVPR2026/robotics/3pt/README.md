# 3D-Object Perception Transformer (3PT)

作者：Agastya Kalra, Tim Salzmann, Guy Stoppi, Dmitrii Marin, Rishav Agarwal, Vage Taamazyan, Martin Bokeloh, Stefan Hinterstoisser, Anton Boykov, Alberto Dall'Olio, Pravin Dangol, Kartik Venkataraman, Huaijin Chen。

方法与配图详细版返工：2026-10-25。展开CAD缓存、旋转融合、互近邻与多视图PnP计算链；未复现实验。

## 一句话总结

3PT把CAD条件检测、姿态候选和多视图RGB精修连接起来，在不输入深度图的条件下提高零样本物体分割与6DoF姿态精度。

## 研究背景与动机

冻结通用模型的提案再匹配流程容易在工业零件、反光和密集堆叠中失败。零样本指不用测试物体专门训练，仍需要已知目标CAD、相机标定，以及大量其他物体的合成训练（第1–3页）。

### 已知什么、要估计什么

已知目标CAD、RGB图像及相机标定；多视图还需要相机间外参。输出每个实例的6DoF姿态、置信度和各视图分割。姿态 \(T\in SE(3)\)包含旋转R和平移t，解释为把CAD物体坐标变换到指定参考系。CAD尺度、相机内外参单位必须一致，不能把毫米CAD与米外参直接组合。零样本指测试物体不专门训练，不是没有CAD或相机信息。（§3，PDF第4–6页）

整个计算有三段：3PT-D为每个目标CAD找框与朝向分布；对象生成将跨视图框组织成实例并初始化多个姿态；3PT-R反复渲染、匹配、几何更新和筛选。精修需要可用初值，不能把它说成从任意姿态全局搜索都能收敛。

## 核心创新与关键设计

### 3PT-D的两组CAD编码用途不同

物体编码器先缓存两种表示。12个固定旋转的渲染经骨干、池化和拼接形成Prior Embeddings，作为图像编码器的条件；另有5140个密集旋转模板的Query Embeddings，用于方向匹配。12不是最终姿态候选数，5140也不是每轮必须精修的假设数。（§3.1，PDF第4页）

图像token与先验token早期拼接后进入ViT，使图像特征从编码阶段就知道正在寻找哪个CAD。回归头预测二维框和置信信息；每个假设特征与模板做余弦匹配，得到朝向分布，正文将检测得分定义为模板相似度最大值。结构图另画MLP score，头输出与最终得分如何组合需实现核查，不能自行相乘。

用Q表示图像假设数、D表示特征维，则假设矩阵Q×D与模板矩阵5140×D归一化后相乘，得到Q×5140相似度矩阵。这个矩阵同时保存多个可能朝向，而不是一次argmax就丢掉所有旋转歧义。先验池化后确切token数和D主文未明确，这里只给接口形状。

多目标场景需要每个CAD分别前向，再跨框NMS；它不是一次前向同时检索任意数量物体。模板缓存节省重复物体编码，但场景图像仍需按目标条件处理。重叠512×512窗口用于pan-and-scan，训练把目标缩放到128–350像素范围；工业场景可用深度范围先验选缩放，BOP不允许固定范围假设时作者用3个尺度覆盖，不能漏掉额外尺度开销。

### 检测训练：位置监督与模板匹配监督不是一个目标

框由L1和GIoU损失监督，假设与对应方向渲染之间用sigmoid focal交叉熵做对比训练。Soft-Scaled Matching对位置接近的非最佳匹配降低惩罚，减少“差一点就正确”却被当硬负例的梯度。主文没有给完整权重函数，不能将“随IoU调整”擅自实现成1/IoU或某固定幂次。（§3.1）

这里训练的是3PT-D网络；推理时模型参数固定。约1B image-render pairs是配对训练口径，不应当作独立航拍/相机图像数量。正文另报90万唯一合成图、约1亿物体实例，三个数分别描述不同层级。

### 单视图初始化：框尺寸给粗深度，不能消除透视歧义

单图每个框成为一个实例。作者用框对角线和CAD对角线的比例初始化z，再把框中心投到该深度得到x、y。针孔相机教学近似为 \(z\approx fD/d\)：焦距f以像素计，物理尺度D以米计，图像尺度d以像素计，则z以米计。假设f=1000、D=.1、d=100，得到z≈1米。该简化不等于论文完整公式，物体姿态、截断、遮挡、框松紧都改变投影尺度。（§3.2，PDF第5页）

给定中心(u,v)，可用 \(x=(u-c_x)z/f_x\)、\(y=(v-c_y)z/f_y\)解释反投影。框中心也未必恰好等于CAD坐标原点投影，所以这只是初始化。朝向从模板分布选Top-K，要求单视图候选间至少45°，保留多个相互区别的模式，避免所有预算都围绕同一个近似角度。

### 多视图初始化：先关联同一实例，再融合旋转

框中心沿各相机射线反投影，通过对极/三角化匹配构造三维位置并去除离群候选。对象组内每个视图最多一个框，作者要求至少3个视图匹配成功才保留。多个相同零件不能只因CAD身份相同就合并成同一实例；需要几何一致性区分。（§3.2）

每个实例有v×5140个朝向提案，作者只取每视图Top-500，再在SO(3)上用各向同性von Mises–Fisher核做KDE重打分，选择保持最小角距的K个提案。旋转必须先变换到同一参考系再融合，不能直接平均不同相机坐标的欧拉角；本文未展开核带宽、旋转表示及具体坐标变换实现。

例如绕同轴179°和−179°实际只差2°，普通数值平均却得到0°，解释了旋转不能当三个普通数随意平均。KDE融合多个相机的视觉证据，减少单视角歧义，但不能保证对真实对称物体选出唯一可辨识姿态。

### 3PT-R的前向：真实图读渲染图，输出匹配特征和评分

每个实例有K个初值、V个标定视图。按检测框裁剪真实RGB并缩放，在每个候选姿态下把CAD渲染进对应视图。真实裁剪与渲染分别经同一个DINOv2编码器。真实视图token作为Q，渲染token作为K/V做交叉注意力；再用DPT解码稠密描述子及分割，register token预测候选分数。（§3.3，PDF第5–6页）

若每个裁剪P个token、维D，单实例单候选的一种接口记法为真实特征V×P×D与对应渲染特征V×P×D；主文“所有render embeddings”的跨视图打包方式、是否跨候选共享注意力并未展开，不能擅自说每个视图读取全部K个竞争姿态。固定裁剪尺寸与特征分辨率也需实现核对。

### 互最近邻把渲染边缘连接到真实像素

设真实特征为F、渲染特征为Z。对渲染边缘像素a找到余弦最相似的真实像素b，再反向查b在候选渲染集合中的最近邻；只有回到a才保留。互近邻排除一部分单向模糊匹配，但不是对应正确性的证明。主文限制到渲染边缘以降低高分辨率匹配成本；不是对全部内部像素作同规模搜索。

渲染像素来自已知CAD，因此有对应物体三维点X；匹配的真实位置给出二维观测u。关键是三维坐标来自渲染几何，不需要实测深度图。假如一条边缘因遮挡对应错了，已知CAD也不会自动纠正真实像素误配。

### 多视图PnP更新的是姿态，不是网络权重

通用几何解释可写成

\[
\min_{R,t}\sum_{v,j}\|\pi(K_v T_{v\leftarrow ref}(R X_j+t))-u_{v,j}\|_2^2.
\]

式中X是CAD点，R、t把它变到参考系，\(T_{v\leftarrow ref}\)再变到相机v，内参与透视除法π产生预测像素，与真实匹配点u比较。这里是便于阅读的重投影目标，不是原文逐字公式；鲁棒核、对应点权重、离群过滤与求解器细节应查作者引用的MV-PnP实现。真实裁剪缩放后必须相应变换像素坐标或相机内参，否则优化的残差坐标不一致。

更新姿态后重新渲染，新的外观与可见边缘改变，下一轮重新匹配；这就是render-and-compare闭环。推理通常3轮，每轮用网络分数淘汰底部50%候选。教学K=8可按8→4→2→1理解，但原文没有因此证明所有配置K都固定8；奇数取整、何时只保留最佳项需核查。

### 精修训练：真姿态监督匹配，扰动姿态训练排序

训练用合成真姿态。给当前假设P渲染后，将渲染三维点按真姿态投到真实图得到目标像素f(a|P)。对其匹配概率做负对数损失：

\[
p_b(a)=\frac{\exp(Z_a\cdot F_b)}{\sum_{b'}\exp(Z_a\cdot F_{b'})},\qquad
L_m=\sum_{a\in Seg[Z]}-\log p_{f(a|P)}(a).
\]

正对应概率升高会降低损失，分母让错误位置竞争；主文没有给出温度、遮挡有效性掩码或亚像素目标取整的完整规则。训练损失写在渲染分割支持上，而推理匹配限制为边缘，两者不能说成相同采样范围。（式1，PDF第6页）

分割用逐像素二元交叉熵。评分训练随机扰动5个初始姿态，执行一步精修后，用softmax交叉熵学习选误差较低的候选；分数目标不是“框里有没有物体”这一个问题。推理候选淘汰依赖这个排序能力，若正确初值被过早低估，后续PnP无法从已删除候选恢复。主文未完整列出精修网络各子模块的冻结策略与损失权重，不将其编造为全量微调或全冻结。

### 计算量和失败边界

检测成本随目标CAD数、尺度与窗口数量增加。精修首轮渲染/前向量与实例数M、候选K、视图V成乘积增长，后续删候选降低成本。互近邻若朴素比较E个边缘特征与P个真实位置，点积工作随EPD增长；这是算法量级说明，未测显存或速度。高精度对CAD单位、表面形状、相机标定与候选覆盖有明确依赖，30.5秒平均H100时延不能称作实时系统。

## 实验与关键结果

第7页BOP-H3检测AP55.1对MUSE41.8；工业AP57.9对34.3。单视图RGB姿态H3 AP58.7对Co-Op46.4，但IC-BIN37.1低于46.7。工业多视图RGB AP-mm80.6对FreeZeRGB-D51.5，比较模态不同。第8页工业平均H100耗时30.5秒；DIMM插入作者96/96成功，容差0.5mm/2°，不等于任意工业场景保证。

## 消融实验与证据强度

第8页在Co-Op初始化上换精修46.4→47.8，换本文检测并单候选55.1，多候选58.7，说明检测初始化贡献较大。工业在FRTPose上加精修68.3→78.3，全方法80.6。CAD词表35k→110k在相同步数下均值AP49.7→54.8，但数据规模、架构和目标共同变化，不能都归于单一设计。

## 局限与讨论

检测按目标物体分别前向，多类别场景耗时增加；不是实时万能检测器。AP惩罚假阳性，与假定已知物体数量的AR不能直接互换，论文另有T-LESS AR表需单列。近似对称、遮挡、CAD误差与标定仍是风险；榜单第一仅视为作者稿件时间点报告。

## 复现提示
